# 已确认的融合架构

## 产品和安装边界

仓库目标为`pancake-github/zzu-nscc-helper`，中文名“郑州超算助手”，非官方且只适用于本平台。首版保持PyQt5并采用GPL-3.0-only。正式测试版目标为`v0.5.0-beta.1`；当前源码整理版本为`0.5.0.dev1`。

统一GUI只展示已安装组件；保活、分流和SFTP可以分别安装或任意组合。公共运行库仅安装一份。仅分流或仅SFTP不要求Edge扩展。首版扩展通过软件内引导手动加载一次，后续商店分发不阻塞测试版。

## 共享接口

- 版本化平台资源：固定平台目标、HTTPS响应判据、SSH身份和允许范围；不包含个人用户名、本地网卡或代理端口。
- 环境检测结果：客户端版本、实际配置目录、监听端口、HTTP或命名管道控制器、VPN接口身份和DNS；控制器密钥仅在内存使用。
- 分流变更计划：源文件哈希、精确增量、原有开关状态、备份身份和验证状态。预览不写入配置。
- 后台任务：独立工作程序通过私有JSON管道接受请求、返回进度、逐项结果、完成或错误，并接收取消；凭据不写入磁盘。
- 安装组件：`keepalive`、`routing`、`sftp`；`core`为共同依赖，不接受任意远程模块名。

## 分流事务

仅对通过测试的Clash Verge Rev版本自动写入。识别真实配置，保留已有增强脚本、订阅、节点、代理组和开关；重复应用不重复追加。五个域名分别处理系统代理绕过、VPN DNS和fake-IP排除，公网入口仅精确排除222.22.12.2/32。

应用顺序为检测、预览、确认、核对哈希、备份、正常退出Clash、写入、重启、核对运行配置与联网状态。拒绝正常退出时等待用户，不强杀。有保活或传输任务时禁止应用。配置错误回滚，VPN未登录标为等待联网验证；出现后续人工修改时报告冲突，不覆盖整份备份。

未知版本、多个候选、特殊PAC和不兼容fake-IP模式不自动修改。SFTP单独验证本平台22端口的VPN路径，不写全局22端口直连或宽泛内网排除。

## SFTP和保活生命周期

复用当前上传下载核心、测试及无覆盖发布语义。GUI仅做路径式批量上传下载与任务展示，首版不做完整远程文件管理器。不复用开发者账号；每批一次认证；上传继续完整回读SHA-256校验，保留逐文件状态和回执语义。

保活沿用真实交互、780秒间隔、20秒硬截止、单次标签恢复、睡眠停止和托盘行为；运行路径及VPN接口识别需在融合阶段解除本机依赖。保活停止不主动取消SFTP；退出整个软件时统一处理所有任务，取消失败和临时清理未确认须如实记录。

## 构建与发布

在GitHub Actions Windows环境构建GUI、独立工作程序、在线和离线安装器，不向开发者现有Anaconda安装构建工具。选中组件与实际下载、安装内容保持一致，校验SHA-256后才安装。

打包后的真实验收必须重新执行，不能沿用源码基线45分钟结果。真实标签恢复、故障单次提醒、进程清理和组件升级也需完成后才发布beta。发布前核对文件白名单及第三方许可，不分发VPN客户端、Clash订阅或个人配置。
