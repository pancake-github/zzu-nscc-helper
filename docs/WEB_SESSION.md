# 网页会话与 VPN 双通道保活

适用版本：主程序 `0.5.0b3` / `v0.5.0-beta.3`，Edge 扩展 `0.5.0`。仅适用于本仓库说明的郑州超算平台，非官方项目。

## 修改原因

此前的独立 HTTPS 请求访问平台前端 HTML，能产生 VPN 内网流量，但不携带浏览器登录态。扩展的两秒心跳只是本机通信，也不能代替网页请求。旧版还会因浏览器关闭或登录地址变化停止 VPN 保活。因此，网页登录过期、重新登录和 VPN 无流量断开的情况可能先后发生。

## 实际请求

| 通道 | 真实动作 | 成功判据 | 间隔 |
| --- | --- | --- | --- |
| VPN | 独立工作进程直连平台前端 HTML | 原有 TLS、VPN 路由、HTTP 200、正文特征及大小检查 | 每次成功后 780 秒 |
| 网页 | Edge 在已绑定页面主上下文调用平台自身 GET 接口 | HTTP 200、JSON 业务码 0、用户身份与页面当前身份一致、角色和令牌列表结构符合预期 | 全部选定页面成功后 780 秒 |

网页接口为 `/ac/api/user/getCurrentUserInfo.action?includeToken=true&refresh=true`。该地址、GET 方法、成功码及 `SET_USER_INFO` 状态更新来自本平台实际前端脚本。实现不会通过请求静态文件冒充已维护网页登录态，也不会刷新整页、上传文件、提交作业或向终端输入命令。

响应中可能包含用户信息与平台服务令牌：这些数据只在原网页内存内处理，并按平台原有逻辑更新该页的会话状态；不会发给桌面、写入日志、上传 GitHub 或另行保存。浏览器自行携带同站点登录态，不调用 Cookie 读取 API，不导出 Cookie。网页请求使用浏览器正常 TLS 行为，不关闭证书验证。

每页请求包括响应读取最多 20 秒、64KiB；禁止重定向和客户端缓存。多个页面串行处理，最多 10 页，不并发、不自动重试。默认仅在点击开始时纳入与所选页相同登录路径的 E-File、计算服务及命令行页面；可取消勾选以只维护所选页。新打开的页面需要手动重新绑定才能加入。

## 停止与重新登录

- 主界面分别显示 VPN 和网页的成功时间、次数、下次交互时间。仅绑定、扩展心跳或静态 HTML 成功不会增加网页成功轮数。
- 网页关闭、改变登录地址、扩展失联、请求失败或业务认证过期：取消网页维护并提醒一次，独立 VPN 保活继续。用户登录后可直接重新绑定，VPN 的计数与定时不重置。
- 新双通道模式不会自动重开关闭的网页，也不会恢复旧登录地址；历史标签恢复实现保留作兼容回归，不作为新模式的运行策略。
- VPN 路由失效、独立 HTTPS 失败、电脑睡眠或调度明显延迟：停止两种请求。手动停止和退出也取消两种请求；停止 VPN 不主动取消独立 SFTP 传输。
- 不自动重新登录，不绕过服务端强制登出、最大会话寿命或权限撤销。已打开终端的 SSH/WebSocket 连接有独立生命周期；刷新平台会话不等于重建终端连接。

## 升级与验证范围

在线和离线安装器统一包含上述模块，不需要另装补丁。升级前从托盘退出助手，安装后将内置 Edge 扩展重新加载一次，确认版本为 0.5.0。首次启动必须自行选择业务页并点击开始。

离线测试覆盖：两类计数和计时分离、浏览器断开后 VPN 继续、网页登录过期后重绑、VPN 失败与睡眠同时取消、迟到响应不复活；浏览器测试核对真实 GET 地址、自动同站点认证、状态更新、失败响应、大小上限、超时、取消和重复指令。安装包及真实联网结果以对应 Release 和阶段记录为准；不能把离线用例或十几分钟运行宣称为已验证隔天永不掉线。
